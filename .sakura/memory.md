## 审查检查表

1. **重复检测必须可审计**：给出检索范围、关键词/阈值、候选摘要与异同；最终结论保持唯一。无重复也要声明证据，不能同时写“未发现”与“可能重复”。
2. **分类—标签—动作一致**：Bug 修复不混标 `enhancement`；功能已存在归 `question`+`documentation`；垃圾 Issue 归 `other`+`invalid` 并直接关闭，必要时锁帖/清理评论。
3. **标签须可落地**：先核验仓库已有标签，区分“语义建议”与“实际可添加”；未确认贡献意愿时 `help wanted` 置信度宜 0.5~0.6；多文件、配置兼容或框架知识任务不标 `good first issue`。
4. **优先级看影响范围**：审核绕过、漏报、误罚及核心配置失效倾向 `high`；提供商兼容问题需确认工具是否默认注册、是否使全部请求失败，否则可降 `medium`；`critical` 仅用于安全绕过、全群异常、数据泄露等。
5. **方案分层并推荐起点**：明确最小修复与高级方案，优先低风险方案；估算需包含回归测试、外部冒烟和环境成本。外部库/LLM 必须有超时、并发限制、`ImportError` 或默认动作降级。
6. **标题按需优化**：原标题模糊、冗余或过短时补充对象、现象和根因；标题通常不重复写优先级，原题已清晰则不强改。

## 关键技术经验

- **工具 Schema（ISSUE62）**：Gemini 会在执行前严格校验全部函数声明，单个非法 Schema 可能令整次请求 400。数组除 `type: array` 外必须有合法 `items`；AstrBot 文档参数可先尝试 `list[string]`，但修改 Python 注解前须确认目标版本的 Schema 来源、语法支持及注解/文档优先级，谨慎使用联合类型。
- **Schema 测试**：按工具名称查找，禁止依赖 `function_declarations[23]` 等易变索引；通用断言所有数组节点均含 `items`，再做可选 Gemini 冒烟，不以外部 API 作为 CI 唯一保障。
- **声明层与执行层分离**：`_normalize_id_list` 能接收列表不代表工具声明正确；先定位错误发生于声明、生成 Schema、适配器还是业务执行层。
- **审核顺序（ISSUE55）**：通过词应在违禁词库/广告检查前放行；配置开关必须覆盖所有相关路径。修复已有配置失效属于 `bug`，新增 WebUI 开关才是 enhancement。
- **反刷屏占位符（ISSUE61）**：OneBot 图片等会映射为固定占位符；多张正常图片不应因重复 `[图片]` 被判“无用消息”。最小方案跳过纯占位符，高级方案显式记录 `has_unique_text`，并检查统计副作用。
- **LLM 审核（ISSUE56）**：优先复用 `_call_llm_safe`、协议剥离、信号量和超时；默认关闭并在不可用时回退原动作。涉及配置、WebUI、Mixin 的多文件改动不适合新人任务。
- **协议字段处理**：审核前统一剥离 OneBot 拼接片段；推动通用 `strip_protocol_fragments`，非文本消息需明确是否打断短消息窗口。
- **Mixin 维护**：`Main` 集中继承多个 Mixin，新增能力须同步维护继承清单并检查 MRO（左高右低）。
- **平台约束**：OneBot 撤回窗口约 2 分钟、禁言最小粒度 60 秒；可行性分析需显式引用。

## 仓库模式

- 审核链路：AC 自动机初筛 → LLM 二次判断 → 撤回/说明；SQLite 保存审核日志与外置词库 `lexicon.db`。
- 踢人、禁言等多入口应收敛到共享方法，避免配置与修复只覆盖部分路径。
