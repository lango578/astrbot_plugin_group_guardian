# 跨入口变更检查表

用于配置、群管动作、审核规则、命令和 Mixin 的改动；目标是防止“只修一个入口”的回归。

## 1. 先枚举入口

修改前搜索同一业务动作的全部调用点，至少检查：

- 聊天指令（`commands.py`）
- LLM 工具（`llm_tools.py`）
- WebUI / 跨群操作（`web.py`、`remote.py`）
- 自动审核与加群审核（`moderation.py`、`membership.py`）
- 定时任务或申诉流程

踢人、禁言、撤回等动作应收敛到共享方法；共享方法统一处理权限、配置、协议错误、日志和限速。

## 2. 配置是行为契约

新增或修改配置时必须同步检查：

1. `_conf_schema.json` 的类型、默认值、范围和说明；
2. 每群覆盖及排除列表；
3. WebUI 读写映射；
4. README、CHANGELOG、命令帮助；
5. 开关是否覆盖所有辅助路径，而非只控制主路径；
6. 默认值是否保守并保持升级兼容。

已有开关未控制完整路径属于 `bug`；新增控制粒度才属于 `enhancement`。

## 3. Mixin 与注册

- 新增 Mixin 后更新 `Main` 继承清单，核对 MRO 左高右低。
- 新增方法还要检查装饰器、命令别名和工具是否实际注册。
- CI 应实例化 `Main`，按名称验证注册入口依赖的方法存在。

## 4. 文档可发现性

功能存在但用户反复提问，视为入口设计信号：

- 命令别名同步 README 与 `/help`；
- 配置说明同步 schema 与 WebUI；
- 历史回滚在 CHANGELOG 中醒目标注当前结论；
- 常见咨询加入 FAQ，而不是重复实现同一功能。

## 5. 合并门禁

- 先提交可复现失败的测试，再提交修复。
- 按入口做矩阵回归，确保权限与配置一致。
- 外部服务、系统库和协议失败均有降级路径。
- 检查平台边界：撤回约 2 分钟、禁言最小 60 秒、历史消息约 100 条、批量操作限速。
