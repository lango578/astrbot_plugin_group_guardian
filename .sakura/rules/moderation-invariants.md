# 审核与防刷屏不变量

以下规则适用于消息审核、加群审核、广告检测和反刷屏改动。

## 1. 输入边界

- 审核对象必须是**用户实际输入**，不得直接匹配 OneBot 拼接后的整段字段。
- `message`、`comment` 中的引用原文、验证问题、系统说明应先由统一函数（建议 `strip_protocol_fragments`）剥离。
- 提取失败时可回退原值并记录调试信息；各入口不得自行维护互不兼容的正则。
- 兼容测试至少覆盖 NapCat、LLOneBot 的已知格式，以及纯文字、纯回复、回复+文字、多层引用、问题+答案。

## 2. 审核决策顺序

推荐显式顺序：

1. 提取用户纯输入；
2. 命中通过词则放行；
3. 检查拒绝词；
4. 按配置决定是否检查通用词库；
5. 按配置决定是否检查广告模式；
6. 可选 LLM 二次判断；
7. 执行撤回、拒绝、禁言等动作。

配置开关必须覆盖所有关联分支；禁止出现“关闭词库但广告辅助路径仍调用词库”等半失效状态。已有开关失效属于 `bug`，新增控制粒度才属于 `enhancement`。

## 3. LLM 安全边界

- 新 LLM 审核默认关闭，复用安全调用、信号量和超时。
- 调用失败、超时、解析失败时回退原有默认动作，不阻断主流程。
- 自定义提示词不得移除输出格式约束；应校验结果并提供默认提示词回退。
- 不把外部 API 冒烟测试作为 CI 唯一保障。

## 4. 防刷屏语义

- 消息频率统计与重复内容判定必须解耦。
- `[图片]` 等协议统一占位符不代表内容相同；多张不同图片不得因占位符相同被判“无用消息”。
- 最小修复可跳过纯占位符的重复判定；高级实现应显式记录 `has_unique_text` 或消息标识。
- 短消息拼接仅限同群、同用户、连续短文本且间隔小于约 5 秒；非文本或长文本应打断窗口。
- 拼接命中后的处罚独立于防刷屏，并清空片段状态，防止重复处罚。

## 5. 合并前检查

- 通过词能覆盖词库及广告路径。
- 所有配置开关分别有开启/关闭测试。
- 正常图片连发、混合文本图片、相同文本刷屏均有回归用例。
- 误判场景优先级按业务伤害评估，不因修复代码少而降级。
