# 审核数据流与责任边界

## 数据流

```text
OneBot 事件
  → 协议适配/消息链解析
  → 提取用户纯输入
  → 规则决策（通过词/拒绝词/词库/广告）
  → 可选增强（二维码、短消息拼接、LLM）
  → 群管动作
  → SQLite 审核日志
```

## 层级职责

### 1. 协议层（`onebot.py` / 解析辅助函数）

- 封装撤回、禁言、踢人、历史消息等 OneBot 调用。
- 识别引用块、验证问题等系统附加内容，不参与业务审核决策。
- 记录 NapCat、LLOneBot 等实现差异。

### 2. 纯输入提取层

- 把消息拆成“用户输入、协议拼接内容、元数据”。
- 消息审核与加群审核共用剥离策略；入口只提供格式适配，不复制匹配逻辑。
- 无法识别格式时回退并记录，避免平台升级直接阻断流程。

### 3. 规则层（`moderation.py` / `membership.py`）

- AC 自动机负责大词库快速初筛，正则处理复杂模式。
- 规则优先级是稳定接口，配置项必须控制对应的完整路径。
- `lexicon.db` 保存外置词库，热更新后应同步重建或刷新匹配器。

### 4. 增强层

- 二维码：轻量解码优先，OCR 兜底；缺少 zbar 时警告并降级。解出的 URL 重新进入词库/域名审核。
- 短消息拼接：复用 `anti_flood` 队列，但处罚和状态独立。
- LLM：语义复核而非唯一防线；默认关闭，带并发、超时和失败回退。

### 5. 动作层

踢人、禁言、撤回等多入口应收敛到共享方法，统一权限、配置、日志和错误处理。WebUI 跨群操作必须先将登录身份映射到 QQ，再查询目标群角色，不能把 Web 登录态直接等同于群权限。

## 平台约束

- 撤回窗口约 2 分钟。
- 禁言最小有效粒度 60 秒；用户界面统一输入分钟。
- 群历史消息通常最多取 100 条，批量动作需限速。

这些约束属于产品边界，应同时出现在实现、帮助文本和测试预期中。
