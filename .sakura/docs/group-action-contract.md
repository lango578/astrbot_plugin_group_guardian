# 群管动作与授权契约

## 目标

禁言、解禁、踢人、撤回、设置管理员等动作可能来自聊天指令、LLM 工具、审核联动和 WebUI。入口不同不应改变授权规则、配置语义或错误处理。

## 责任分层

```text
入口解析
  → 操作者身份解析
  → 目标群角色校验
  → 参数归一化
  → 共享动作方法
  → OneBot 适配
  → 审计日志/用户提示
```

### 入口层

只负责解析参数和上下文，不直接复制 OneBot 调用。批量与单人入口使用相同动作原语。

### 身份与授权层

- 聊天指令：从事件发送者取得 QQ 与目标群角色。
- LLM 工具：不得因工具入口而放宽指令权限；模型调用不是可信身份。
- WebUI 跨群：先把登录用户映射到已绑定 QQ，再查询其在**目标群**的角色。
- 设置/取消管理员等群主专属动作，所有入口均执行同一约束。
- 插件管理员权限与群管理员权限含义不同，不可互相替代。

权限不一致形成可利用路径时按缺陷处理；新策略开关才属于增强。

### 共享动作层

共享方法统一负责：

- 配置开关与默认值；
- 操作者/目标成员权限检查；
- OneBot 参数单位转换；
- 频率限制、异常解析和可读提示；
- 审计日志；
- 可选联动行为（如踢人后撤回近期消息）。

## 协议边界

- 用户输入禁言时长统一使用分钟，适配层转换为秒。
- OneBot 禁言最小有效粒度约 60 秒。
- 撤回通常仅对约 2 分钟内消息有效。
- 群历史消息常见上限约 100 条；批量撤回必须限速并允许部分失败。
- 不向用户直接暴露裸 OIDB 错误；应转换成权限不足、超时或协议失败等可理解信息。

## 测试矩阵

每个高风险动作至少覆盖：

| 维度 | 场景 |
|---|---|
| 入口 | 指令、LLM、WebUI、审核联动 |
| 角色 | 群主、管理员、普通成员、未绑定 Web 用户 |
| 目标 | 普通成员、管理员、群主、Bot 自身 |
| 协议 | 成功、权限不足、超时、限速、部分失败 |
| 配置 | 开启、关闭、默认值、每群覆盖 |

测试应断言所有入口最终调用同一共享方法，并产生一致的权限结果与日志。
